# HVE Core GitHub Actions Automation Package

This directory contains an optional GitHub Agentic Workflow package copied from
upstream HVE Core. It is not enabled by installing the Codex plugin. A target
repository must explicitly copy the package into `.github/`.

## Included Workflows

| Workflow | Trigger | Write capability |
|---|---|---|
| `issue-triage` | Issues opened or labeled `needs-triage` | Comments, labels, optional follow-up issues. |
| `issue-implement` | Issues labeled `agent-ready` | Comments and pull request creation. |
| `pr-review` | Pull requests opened, synchronized, or marked ready | Review comments, PR review submission, labels, optional draft conversion. |
| `dependency-pr-review` | Dependabot dependency PRs | Review comments and PR review submission. |
| `doc-update-check` | Relevant pushes to `main` | Documentation follow-up issue creation. |

Each workflow has a source `.md` file and a compiled `.lock.yml` file.

The workflows import HVE Core source artifacts such as `.github/agents/*.agent.md`
at runtime. This package therefore also includes `artifacts/.github/` with the
agents, instructions, skills, and support files the workflows expect.

## Install Into A Repository

From this port repository:

```bash
mkdir -p /path/to/target-repo/.github/workflows
cp -R github-actions/artifacts/.github/* /path/to/target-repo/.github/
cp github-actions/workflows/* /path/to/target-repo/.github/workflows/
```

Review every copied artifact and workflow before enabling it in a production
repository. If the target repository already has HVE or project-specific
`.github` artifacts, merge intentionally instead of blindly overwriting them.

## Required Setup

The upstream lock files are generated by GitHub Agentic Workflows and reference
GitHub Copilot and GitHub MCP runtime secrets. Review the copied workflow files
for the exact current secret names. Commonly referenced names include:

* `COPILOT_GITHUB_TOKEN`
* `GH_AW_GITHUB_TOKEN`
* `GH_AW_GITHUB_MCP_SERVER_TOKEN`
* `GH_AW_CI_TRIGGER_TOKEN`
* `GITHUB_TOKEN`

The target repository also needs the labels referenced by the workflows, such as
`needs-triage`, `agent-ready`, `needs-revision`, and `review-passed`.

The upstream workflows were authored for HVE Core's own repository automation.
Before installing them into a different repository, review sparse checkout paths,
label taxonomy, PR templates, issue templates, and repository-specific
instructions. Some workflow behavior may need adaptation for non-HVE repos.

## Safety Notes

These workflows perform repository write actions when properly configured. The
compiled lock files include upstream safeguards such as activation guards,
allowed label lists, output limits, sparse checkouts, and safe-output handling.

Do not install these workflows into a repository unless maintainers have reviewed:

* workflow permissions
* required secrets
* branch protection interaction
* label policy
* PR review policy
* write actions allowed by the safe-output configuration

## Codex Relationship

The Codex plugin packages HVE Core interactive knowledge and local commands. This
GitHub Actions package provides event-driven automation. Keep those boundaries
separate: plugin install should not silently enable repository automation.
